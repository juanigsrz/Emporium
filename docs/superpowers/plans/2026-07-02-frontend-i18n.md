# Frontend Internationalization (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route every user-facing string in the React frontend through `react-i18next`, add a navbar language switcher, and ship English + Spanish locale files that a contributor can extend with one new file per language.

**Architecture:** `i18next` is initialized once (side-effect import in `main.tsx`) from a small registry that maps locale codes to nested JSON resources. Components read strings via the `useTranslation` hook's `t('namespace.key')`. Zod schemas that carry error messages are rebuilt inside components with a `t`-aware factory. A plain Node script enforces that every locale file has exactly the same key set as the English base.

**Tech Stack:** React 18 + TypeScript + Vite, `i18next`, `react-i18next`, `i18next-browser-languagedetector`, Tailwind.

## Global Constraints

- **Scope: frontend only.** Do not touch the Django backend. No backend text, no DB profile field, no date/number localization.
- **Base locale is `en.json`.** Its key set is the source of truth. Every other locale must match it exactly (the `check:i18n` script enforces this).
- **Two locales ship:** `en` (English) and `es` (Spanish). Every key added to `en.json` gets the same key in `es.json` with a Spanish translation.
- **Key naming:** dot-namespaced, `namespace.camelCaseKey`. Namespaces mirror `features/`: `common`, `nav`, `auth`, `login`, `home`, `events`, `trades`, `copies`, `matching`, `profile`. Truly generic, reused strings (Save, Cancel, Delete, Loading, common error toasts) go under `common`.
- **Every task's gate, run from `frontend/`:**
  - `npm run check:i18n` → prints `i18n locales OK (...)`, exits 0.
  - `npx tsc -b` and `npm run lint` → **no error/warning other than the known
    pre-existing baselines**: `HomePage.tsx:14` (unused react-query destructure,
    TS6198 + 4 no-unused-vars) and `CopyForm.tsx:15` (react-refresh warning).
    Task 3 removes the `HomePage.tsx:14` baseline (see its steps); after Task 3
    only the `CopyForm.tsx:15` warning may remain, and Task 6's schema move may
    clear that too. A task introducing any *new* tsc/lint error fails its gate.
  - After any task that changes UI: `npm run dev`, switch the navbar language, confirm the touched screens flip language and the choice survives a reload.

### Shared extraction patterns (apply in every extraction task)

**Pattern A — string replacement.** Add `const { t } = useTranslation()` at the top of the component. Replace each hardcoded user-facing string (JSX text, `placeholder`, `aria-label`, `title`, `alt`, toast/error strings, `<option>` labels) with `t('ns.key')`. Add each key to both `en.json` (exact source string) and `es.json` (Spanish). Interpolate values with `t('ns.key', { count })` and `{{count}}` in the JSON. Do NOT translate: CSS classes, route paths, API field names, enum *values* sent to the backend (translate only the human-readable *label* shown for them), console logs, code comments.

**Pattern B — Zod schema with `t`.** A module-scope `z.object({...})` cannot call `t`. Move it into the component as a memoized factory:

```tsx
import { useMemo } from 'react'
import { useTranslation } from 'react-i18next'
// ...
const { t } = useTranslation()
const schema = useMemo(
  () =>
    z.object({
      field: z.string().min(1, t('ns.errors.fieldRequired')),
    }),
  [t],
)
type FormValues = z.infer<typeof schema>
const { register, handleSubmit } = useForm<FormValues>({ resolver: zodResolver(schema) })
```

If the `z.infer` type is imported by another file, keep an exported standalone schema for the type only (`export const fieldSchemaShape = z.object({...})` without messages) OR export the `FormValues` type from a shared types line — pick whichever keeps existing imports compiling; note it in the task's commit.

**Pattern C — label maps.** A `Record<string, string>` of human-readable labels (e.g. `CONDITION_LABELS`, status labels) becomes a function of `t`. Replace the constant with a lookup at render: `t('ns.condition.' + value)`, or a small `const label = (v: string) => t('ns.condition.' + v)` inside the component. Move the English strings into the JSON under a sub-object so keys stay flat-diffable.

- [ ] **Step 2: Write the parity script**

Create `frontend/scripts/check-i18n.mjs`:
```js
import { readFileSync, readdirSync } from 'node:fs'
import { fileURLToPath } from 'node:url'
import { dirname, join } from 'node:path'

const here = dirname(fileURLToPath(import.meta.url))
const dir = join(here, '..', 'src', 'i18n', 'locales')

function flatten(obj, prefix = '') {
  const keys = []
  for (const [k, v] of Object.entries(obj)) {
    const key = prefix ? `${prefix}.${k}` : k
    if (v && typeof v === 'object' && !Array.isArray(v)) keys.push(...flatten(v, key))
    else keys.push(key)
  }
  return keys
}

const files = readdirSync(dir).filter((f) => f.endsWith('.json'))
const base = 'en.json'
const baseKeys = new Set(flatten(JSON.parse(readFileSync(join(dir, base), 'utf8'))))

let failed = false
for (const f of files) {
  if (f === base) continue
  const keys = new Set(flatten(JSON.parse(readFileSync(join(dir, f), 'utf8'))))
  const missing = [...baseKeys].filter((k) => !keys.has(k))
  const extra = [...keys].filter((k) => !baseKeys.has(k))
  if (missing.length || extra.length) {
    failed = true
    console.error(`\n${f}:`)
    if (missing.length) console.error(`  missing: ${missing.join(', ')}`)
    if (extra.length) console.error(`  extra:   ${extra.join(', ')}`)
  }
}

if (failed) {
  console.error('\ni18n locale key parity check failed.')
  process.exit(1)
}
console.log(`i18n locales OK (${files.length} files, ${baseKeys.size} keys).`)
```

```tsx
import { useTranslation } from 'react-i18next'
import { languages } from '../i18n/locales'

export default function LanguageSwitcher() {
  const { t, i18n } = useTranslation()
  return (
    <select
      aria-label={t('nav.language')}
      value={i18n.resolvedLanguage}
      onChange={(e) => i18n.changeLanguage(e.target.value)}
      className="rounded-2xl border-2 border-transparent bg-transparent px-2 py-1.5 text-sm font-semibold text-moss transition-colors hover:border-ink/30 hover:bg-sage/40 focus:border-ink focus:outline-none"
    >
      {languages.map((l) => (
        <option key={l.code} value={l.code}>{l.label}</option>
      ))}
    </select>
  )
}
```
